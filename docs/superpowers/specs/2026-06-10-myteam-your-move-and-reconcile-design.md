# My Team — "Your Move" + Frame Reconciliation Design

**Date:** 2026-06-10
**Branch:** `redesign/my-team-first` (LOCAL ONLY — no push / no deploy until user tests with their users)
**Workstream:** 1 of 4 in the My-Team-first redesign. (2 = cut category redundancy, folds in here; 3 = within-position ranking; 4 = roster intelligence.)
**Extends:** `memory/my-team-first-redesign-spec.md`, `docs/superpowers/plans/2026-06-10-myteam-value-balance-and-snapshot.md`

## Problem

The My Team page (category baseball) diagnoses well but isn't decision-first. The `/impeccable critique` found two structural faults:

1. **Two competing decision frames.** The This-Week band (matchup win-prob) and the "Where You're Losing" cards (season ranks) carry equal visual weight and point at different categories, so the user can't tell *what to do to win this week's matchup*.
2. **Under-prescriptive.** For "the tool that tells you what to do," there is no single surfaced action. The adds are season-framed ("+12 HR"), not matchup-framed.

Plus three views of the same category-strength data (band statuses, Losing/Edge cards, Profile sliders).

## Goal

Make this-week the spine of the page and surface a ranked short stack of **the highest-leverage actions to win this week's matchup**, each scored in one honest currency: projected win-probability lift. Demote season to context. Collapse the redundant category views into one.

## Approach (chosen)

**Unified candidate-action engine.** Every candidate move — a waiver **add**, a pitcher **stream**, or a **start/sit** swap — is generated by a per-kind *generator*, then scored by a single *scorer* (projected win-prob lift on this week's matchup, via the existing `calcOverallWinProb`). All candidates compete in the same ranking. The page leads with #1 and shows 2-3 next-best.

Why this over alternatives: a per-category list (rejected) drifts back toward a data dump; three disconnected lists (today) can't be compared. Scoring everything in win-prob lift makes "your move" trustworthy and lets a stream beat an add beat a lineup swap on merit.

## Page IA (reconciled)

Top to bottom:

1. **Verdict header** — identity + season standing, punchier copy with a take (e.g. "Elite K's, can't buy a homer.").
2. **YOUR MOVE** *(new hero)* — ranked short stack:
   - #1 prominent: `<action> → +N% · flips <cats>` with a one-line rationale.
   - 2-3 smaller next-best beneath.
3. **This Week** band — primary frame (win %, projected record, coin-flip / safe / loss cats). Existing `MatchupSnapshot`, promoted.
4. **— season-long —** divider.
5. **Season** (demoted, de-duplicated): the Category Profile becomes the *single* canonical category-strength view. The Losing/Edge cards stop duplicating ranks and become purely prescriptive pointers into Your Move, or are removed if Your Move covers them. Visually secondary (smaller, muted).
6. **Roster** — unchanged this workstream (workstream 4 target).

## Engine architecture

New module `src/myteam/yourMove/`.

```ts
// types.ts
export type ActionKind = 'add' | 'stream' | 'startSit'

export interface CandidateAction {
  kind: ActionKind
  player: { key: string; name: string; team: string; position: string }
  // add: drop target (optional). stream: drop target. startSit: the player benched in the swap.
  counterparty?: { key: string; name: string }
  categories: string[]          // this-week cats the move moves
  winProbLift: number           // percentage points vs baseline this-week matchup
  rationale: string             // human-readable, opinionated
}
```

### The scorer (the unifying currency)

`scoreCandidate(candidate, baseline)`:
1. Start from this-week baseline team stat totals (the same `myStats` the snapshot feeds `calcOverallWinProb`).
2. Apply the candidate's **projected remaining-week contribution** (see primitive below) — added for an add/stream/started player, removed for a dropped/benched player.
3. Recompute `calcOverallWinProb` with the modified totals.
4. `winProbLift = newWinPct - baselineWinPct`.

Rank all candidates by `winProbLift` desc; keep the top 1 + next 2-3 for the short stack. Drop candidates with lift below a small floor (e.g. < 1pt) so we never show noise as a "move."

### Core analytical primitive: remaining-week projection

`projectRemainingWeek(player, daysOrGames)` → `Record<statId, number>`: the player's expected stat accrual over the rest of the fantasy week.
- **Hitters:** season per-game rates (or FG ROS where matched via `projectionService`) × expected remaining games. v1 expected-games = remaining days (proxy); Phase 2 replaces with real games-per-week from the schedule service.
- **Pitchers (stream):** projected starts this week × per-start line (IP, K, ER→ERA/WHIP impact) from season rates / FG ROS. Phase 2 supplies starts-this-week + two-start detection from the schedule service.
- Ratio cats (ERA/WHIP/AVG) are volume-weighted the same way the value model already does, so a one-start stream can't swing a rate unrealistically.

This primitive is the main new analytical surface and must be unit-tested in isolation.

### Generators

| Generator | Input | Produces | Data verdict |
|---|---|---|---|
| `addGenerator` | FA pool (`useAvailablePlayers`) × this-week flippable cats | add candidates (best FA per flippable cat) | ✅ ready (all platforms with FA fetch) |
| `startSitGenerator` | my roster + lineup-slot data | bench-a-hurter / start-a-helper swaps | ✅ ESPN (`lineupSlotId`), Sleeper (`starters[]`); ⚠️ Yahoo needs `selected_position` parse (Phase 3) |
| `streamGenerator` | FA starting pitchers × MLB schedule | stream candidates (2-start weeks, matchup) | 🆕 needs schedule service (Phase 2) |

"Flippable cats this week" = snapshot categories with status `tossup`, or `loss` where the gap is within reach. Source: `useThisWeekMatchup` snapshot.

### New service: MLB schedule (Phase 2)

`src/services/mlbSchedule.ts` — wraps `statsapi.mlb.com` (free, public, no auth).
- `getWeekSchedule(startDate, endDate)` → per MLB team: games this week, and per-game `probablePitcher` (playerId, name).
- Derived: `gamesThisWeek(teamAbbr)`, `startsThisWeek(pitcherName|id)`, `isTwoStartWeek(pitcher)`.
- Cached for the day. Name/ID matching reuses the `buildPlayerMatchers` approach from `projectionService`.
- Also feeds the projection primitive (real games-per-week) and can later replace the win-prob engine's `days`-only volatility with game-count volatility.

## Phasing

Each phase is independently shippable and testable, and stays local.

## Edge cases & states

- **No flippable cats** (matchup already decided / very early): Your Move shows a calm "No swing moves right now — you're {favored/behind} {N}-{M}" instead of a forced bad action.
- **No candidates clear the lift floor:** same calm state; never surface a < 1pt "move" as if it matters.
- **FA / schedule / lineup data missing for a platform:** that generator yields nothing; the others still run; never error the page. (We just hardened the Yahoo pool against exactly this class of failure.)
- **Completed week:** Your Move hides; This Week shows Final.
- **Loading:** skeleton for the Your Move block; never blank.

## Testing

- `projectRemainingWeek`: hitters scale by games; ratio cats volume-weighted; FG-matched vs season-rate paths; zero-games → zero contribution.
- `scoreCandidate`: a candidate that improves a tossup raises win-prob lift; a strictly-worse swap is ≤ 0; volume guards prevent a one-start ratio swing.
- Each generator: produces candidates only for flippable cats; respects platform data availability (e.g. startSit yields nothing without lineup slots).
- `rankMoves`: orders by lift, applies the floor, returns ≤ short-stack size, leads with the max.
- Component: `YourMove.vue` renders the hero + next-best, and the calm empty state.
